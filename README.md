# Лабораторная работа №4. Асинхронный исполнитель задач


## Цель работы
Научиться реализовывать приложения с асинхронной моделью управления.
## Постановка задачи
Реализовать асинхронный исполнитель задач, обрабатывающий задачи из
очереди с использованием расширяемых обработчиков.

## Атрибуты задачи
- идентификатор задачи;
- описание задачи;
- приоритет;
- статус задачи;
- время создания;
- вычисляемые свойства (готовность к выполнению, возраст задачи);

### Примеры источников задач:
- задачи, загружаемые из файла;
- задачи, генерируемые программно (генератор);
- задачи, получаемые из API-заглушки (под API-заглушкой понимается упрощённый
программный компонент, имитирующий внешний источник задач);

### Логирование
Не блокирует цикл событий, пишет логи в файл lab4.log(перезаписывается после каждого запуска)

## Вывод
В работе рассматривалась асинхронная модель на базе asyncio: конкурентность обеспечивается кооперативно за счёт await, а обмен задачами между корутинами — через asyncio.Queue в схеме producer–consumer с воркерами; ограничение размера очереди даёт обратное давление на производителя. Управление жизненным циклом исполнителя естественно оформляется асинхронным контекстным менеджером (async with), а расширяемость обработки задач — контрактом в виде typing.Protocol (TaskHandler), который позволяет подключать новые классы обработчиков без смены протокола взаимодействия с очередью.
Практически реализован асинхронный исполнитель с несколькими воркерами, ожиданием завершения через join/task_done и остановкой по sentinel-значениям; задачи подаются напрямую из источников (TaskSource). Выбор обработчика выполняется по приоритету задачи; для модели Task использованы переходы статусов при запуске и завершении. Логирование настроено так, чтобы не перегружать цикл событий синхронной записью, с выводом по уровням в файл и консоль.
