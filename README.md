## Вывод
В работе реализована очередь задач `TaskQueue` как пользовательская коллекция. По теории различают итерируемый объект (Iterable) и итератор (Iterator): у коллекции должен быть метод `__iter__`, который при каждом вызове возвращает новый итератор; завершение обхода согласовано с протоколом через исключение `StopIteration`, которое в обычном коде обрабатывается конструкциями `for` и функциями вроде `list()` без явного `try`. Для повторного обхода одной и той же логической очереди недостаточно хранить одноразовый генератор: очередь хранит контрактный источник `TaskSource` и при каждом обходе снова вызывает `get_tasks()`.
Фильтрация реализована лениво: для отбора по статусу и приоритету используются генераторные выражения, для отбора готовых к выполнению задач — генераторная функция с `yield`; объединение с потоком задач из источника выполняется через `yield from` во вспомогательном обходе. Таким образом, элементы не обязаны одновременно находиться в памяти в виде полного списка внутри очереди — поток задаётся источником, а очередь лишь организует повторяемые обходы и фильтрацию поверх этого контракта. Функция `fetch_tasks` выполняет роль runtime-проверки соответствия протоколу `TaskSource` и возвращает проверенный источник для последующей передачи в очередь.
